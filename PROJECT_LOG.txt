--------------------------------------------------------------------------------
  WHAT IS THIS PROJECT?
--------------------------------------------------------------------------------

iPreneur is an AI-powered SaaS platform that turns a company URL into an
investor-grade PowerPoint pitch deck automatically, in roughly 2 minutes.

User flow:
  1. User pastes a company URL (e.g. https://stripe.com)
  2. The system crawls the site, extracts brand identity
  3. AI agents research the market and competitors
  4. AI generates content for 12 pitch deck slides in parallel
  5. A .pptx file is rendered and uploaded to cloud storage
  6. User downloads the editable presentation

Project folder: pitch DEck/ipreneur/
Git status: repository initialized, NO commits yet (all files are untracked)

ANALYSIS PIPELINE TASK (app/workers/tasks/analysis.py):
  Task name: "tasks.analysis.run_pipeline"
  Max retries: 2 (with 30s delay)
  Auto-retry on: timeout or connection errors

  The pipeline runs these 6 steps IN ORDER:
    Step 1 (0-15%):   WebCrawler (httpx + BeautifulSoup)
                      → Crawls up to 5 priority pages
                      → 30 second timeout per crawl
                      → Output: pages, text summary, colors, images

    Step 2 (15-30%):  BrandingExtractor (Gemini AI)
                      → Analyzes colors, logo, fonts from crawl data
                      → Classifies industry + tone using Gemini
                      → Output: companyName, colors, industry, tone, tagline

    Step 3 (30-55%):  ResearchAgent (Gemini AI)
                      → System prompt: expert VC analyst
                      → Researches: market size, competitors, trends
                      → Output: marketSize, competitors, trends, painPoints

    Step 4 (55-80%):  ContentGenerationAgent (Gemini AI)
                      → Generates 12 slides IN PARALLEL (asyncio.gather)
                      → Each slide has its own dedicated prompt
                      → Structured JSON response per slide
                      → Output: slides[], theme, metadata

    Step 5 (80-95%):  PPTRenderer (python-pptx)
                      → Applies brand colors + fonts
                      → Creates cover, closing, and content slides
                      → 16:9 widescreen (13.33" × 7.5")
                      → Output: .pptx bytes

    Step 6 (95-100%): StorageClient (S3/MinIO)
                      → Uploads presentation.pptx
                      → Generates thumbnail
                      → Returns public HTTPS download URL

  After completion:
    → Updates Project record: status="ready", saves branding/research/deck_content
    → Creates Presentation record in database
    → Updates Job record: status="completed"

  On failure:
    → Updates Job: status="failed", saves error message
    → Updates Project: status="error"
    → Retries if error is timeout/connection related

--------------------------------------------------------------------------------
  SUMMARY OF MAJOR DECISIONS MADE
--------------------------------------------------------------------------------

1. MONOREPO STRUCTURE — all code in one repo: frontend/, backend/, shared/
2. DARK PREMIUM DESIGN SYSTEM — Obsidian (#0A0716) background, Electric Blue
   → Violet gradient, Inter font. Matches AI-native SaaS aesthetic.
3. ASYNC PIPELINE VIA CELERY — AI work is long-running (2+ min), so it runs
   in a Celery worker, not the API request. UI polls for progress.
4. POLLING NOT WEBSOCKETS — WorkspacePage polls every 3 seconds instead of
   opening a persistent WebSocket (simpler to implement, sufficient for this UX)
5. 12 SLIDES IN PARALLEL — ContentGenerationAgent uses asyncio.gather so all
   12 slide prompts are sent to Gemini simultaneously, cutting generation time.
6. PYTHON-PPTX FOR RENDERING — Custom PPTRenderer rather than a third-party
   template system, giving full control over layout.
7. PYDANTIC V2 — Backend schemas use Pydantic v2 (model_config, from_attributes)
8. GEMINI AI — Google Gemini API (gemini-2.5-flash) is the primary AI provider
   with 8192 token context window.
9. MINIO FOR LOCAL DEV — S3-compatible local storage so developers don't need
   an AWS account. Same code works in production with real S3.
10. JWT + REFRESH TOKENS — Short-lived access tokens (30 min) + long refresh
    tokens (30 days) stored in localStorage via Zustand persist middleware.
11. LIGHTWEIGHT CRAWLER — httpx + BeautifulSoup instead of Playwright for
    faster, simpler crawling without browser overhead.
